# CLAUDE.md

Ce fichier guide Claude Code (claude.ai/code) quand il travaille dans ce dépôt.

## Ce que c'est

**Wisp** est une extension Chrome (Manifest V3), suite de **Tab Ghost**. Elle regroupe automatiquement les onglets par sujet (domaine, ou domaines liés manuellement) et endort les groupes inactifs pour libérer la RAM. Contrairement à Tab Ghost, la logique n'est plus "un timer par onglet" mais "activité au niveau du groupe" + "regroupement par contenu, pas par temps".

## Développement & tests

Pas d'étape de build — HTML/CSS/JS vanilla chargé tel quel dans Chrome.

**Pour tester :**
1. `chrome://extensions`
2. Active "Mode développeur"
3. "Charger l'extension non empaquetée" → sélectionne ce dossier
4. Recharge l'extension après toute modif de `background.js` ou `manifest.json`
5. Les modifs de `popup.html`/`popup.js` s'appliquent à la prochaine ouverture du popup

**Pour déboguer le service worker :** sur `chrome://extensions`, clique sur le lien "service worker" sous Wisp.

### Tests automatisés — méthode TDD

`npm test` lance les tests (lanceur intégré à Node, aucune dépendance). `tests/charger.mjs` exécute le **vrai** `background.js` dans un contexte `vm` avec un faux `chrome` qui accepte tout appel : les fonctions pures (`getTopic`, `planSearchGroup`, `keywordsOf`…) se testent telles qu'elles partent dans l'extension, sans copie ni module. Les `let` de premier niveau (`LINKED_DOMAINS`…) se modifient via `w.evaluer("...")`. Les objets rendus par le contexte vm ont un autre `Array.prototype` : les repasser par `JSON` avant un `deepEqual`.

Toute modification suit le cycle **rouge → vert** :
1. Écrire d'abord le test qui décrit le comportement voulu, et le voir **échouer**
2. Écrire le code minimal qui le fait passer
3. `npm test` entièrement vert avant tout commit

Un bug corrigé commence par un test qui le reproduit. Exemple fondateur : `getTopic()` rendait `null` pour Gmail et Gemini, parce que `NEVER_GROUP` (qui contient `google.com`) était testé avant `SERVICE_HOSTS`. Le test « les services Google sont des sujets distincts » l'a révélé.

### Livraison

- **Commit + push sur GitHub après chaque changement validé** (tests verts). Le dépôt ne versionne que l'extension : `site/` est exclu par `.gitignore`, tout comme `tools/licence-privee.json`, qui ne doit **jamais** être publiée.
- `npm run package` fabrique `dist/wisp-<version>.zip` pour le Chrome Web Store, **seulement si tous les tests passent**. Le zip contient la liste explicite `FICHIERS` de `tools/empaqueter.mjs`, que `tests/paquet.test.mjs` confronte à ce que le manifeste et le popup font réellement charger (sans ce test, `_locales` a failli rester hors du zip, et le Store aurait refusé le paquet) ; il refuse une version déjà empaquetée — monter `version` dans `manifest.json` avant chaque envoi au Store.
- GitHub Actions (`.github/workflows/tests.yml`) relance les tests à chaque push.

## Architecture

- **`logo-wisp.png`** — le logo source, fourni par l'utilisateur : trois pastilles aux couleurs des groupes d'onglets Chrome. C'est le seul visuel du projet. `icon16/32/48/128.png` en sont dérivées par recadrage sur le contenu (`getbbox()`) plus une marge uniforme de 7 %, et non par simple redimensionnement : le fichier d'origine porte ~19 px de marge latérale qui rendaient la marque trop petite à 16 px. Les tailles sont fournies explicitement plutôt que laissées au redimensionnement de Chrome. Le fond est transparent et tient sur barre d'outils claire comme sombre.
- **`_locales/fr` et `_locales/en`** — l'extension parle la langue du navigateur : français pour un Chrome en français, **anglais partout ailleurs** (`default_locale: "en"`). Le nom et la description du manifeste passent par `__MSG_extName__` / `__MSG_extDescription__`. Dans le code, tout texte visible passe par `t("clé", [valeurs])` — une fonction de trois lignes dupliquée dans `background.js` et `popup.js`, qui retombe sur la clé si un message manque (un oubli se voit au lieu de donner un titre de groupe vide). Le popup porte ses clés en attributs `data-i18n`, `data-i18n-placeholder`… que `applyI18n()` remplit avant tout rendu. Les deux fichiers ont exactement les mêmes clés ; `tests/i18n.test.mjs` y veille, ainsi qu'à l'absence de clé morte ou de texte en dur. Les valeurs à insérer utilisent les placeholders Chrome (`$P1$` → `"$1"`)
- **`manifest.json`** — MV3. Permissions : `tabs`, `tabGroups`, `storage`, `alarms`, `contextMenus`. Pas de `host_permissions` (contrairement à Tab Ghost) : on ne touche plus au `document.title` des pages, donc pas besoin de `scripting` ni `<all_urls>`.
- **`background.js`** — Service worker, toute la logique :
  - `getBaseDomain()` / `getTopic()` — extraction du domaine et résolution vers un "sujet". Ordre de priorité dans `getTopic()` : protocole http(s) uniquement → `LINKED_DOMAINS` (hostname puis domaine de base) → `SERVICE_HOSTS` → `NEVER_GROUP` → domaine de base
  - `prettyTopic()` / `BRAND_NAMES` — rend le sujet lisible : « GitHub » et non `github.com`
  - `SERVICE_HOSTS` — hôtes multi-services où le domaine de base ne veut rien dire (`mail.google.com` ≠ `gemini.google.com` même si tous deux sont `google.com`). Chaque service est un sujet à part entière (trois onglets Gmail donnent « Gmail »), et la catégorie `google` du lexique les rassemble quand aucun n'atteint seul le seuil (Gmail + Drive + Ads donnent « Google »). Gemini reste dans `ai`, avec ChatGPT et Claude. Un hôte Google absent de cette table retombe sur `google.com`, donc sur `NEVER_GROUP` : il n'a alors ni sujet ni catégorie
  - `NEVER_GROUP` — moteurs de recherche et portails, exclus du regroupement **par domaine** : une recherche Google n'est pas un sujet en soi. Ils restent en revanche rattachables à un sujet par `groupBySearchSession()`, via leur requête — c'est ce qui permet à deux onglets de résultats sur Lisbonne de se retrouver ensemble
  - `pickColor()` — attribue à chaque nouveau groupe une couleur encore libre dans la fenêtre (palette `PALETTE`), pour que deux groupes voisins ne se ressemblent pas
  - `maybeAutoGroup()` — appelé à chaque chargement complet d'onglet (`tabs.onUpdated`, `status === "complete"`). **Trois chemins, du plus précis au plus large** : `groupBySearchSession()` (l'intention exprimée) → domaine (`MIN_TABS_TO_GROUP` onglets sur un même sujet) → `groupByCategory()` (le métier du lexique). L'ordre compte : trois onglets Amazon donnent « Amazon », pas « Achats »
  - `sweepExistingTabs()` — **`maybeAutoGroup()` ne se déclenche que sur `tabs.onUpdated`**, donc uniquement quand un onglet finit de charger. Les onglets déjà ouverts au démarrage de l'extension n'étaient jamais examinés : on pouvait avoir quatre sites d'achat sous les yeux sans qu'aucun groupe n'apparaisse, et un rechargement de l'extension ne changeait rien. Ce balayage est lancé par `onInstalled`, `onStartup`, et par le bouton « Ranger les onglets ouverts » du popup. Il relit chaque onglet (`tabs.get`) plutôt que de se fier à l'instantané de `windows.getAll`, qui vieillit à mesure qu'on groupe. Il **rend le nombre d'onglets rangés**, que le popup affiche (« 5 onglets rangés » / « Rien à ranger ») : sans retour, « rien à faire » et « en panne » se ressemblaient. Chaque onglet a son propre `try/catch` — un bloc englobant abandonnait tout le balayage à la première erreur, en silence — et seules les fenêtres `normal` sont parcourues : Chrome refuse de grouper dans une fenêtre d'application (PWA) ou de popup
  - `CATEGORY_HINTS` ne porte que des **identifiants** (`shopping`, `ai`, `travel`…) ; `categoryOf(clé)` rend le nom affiché via `t("category_<id>")`. Tout lecteur du lexique passe par `categoryOf()`, jamais par `CATEGORY_HINTS[…]` directement
  - `groupByCategory()` / `categoryOfUrl()` — Vinted, Amazon, AliExpress et Cdiscount n'ont aucun domaine commun mais relèvent tous d'« Achats ». Ce chemin **n'écrit rien dans `LINKED_DOMAINS`** : il forme le groupe, point. Le mapping permanent reste une décision de l'utilisateur, prise depuis la suggestion du popup. Un sujet défini à la main prime toujours sur le lexique
  - `searchQueryOf()` / `groupBySearchSession()` — **le seul chemin qui regroupe des domaines sans rien en commun**. Une requête est mémorisée dans `chrome.storage.session` sous `q_<tabId>` par **deux** voies : `tabs.onCreated` lit l'`openerTabId` (onglet ouvert *depuis* une page de résultats), et `stampSearchQuery()` estampille la page de résultats **elle-même** à son chargement. Sans cette seconde voie, taper deux recherches à la suite dans la barre d'adresse ne produisait jamais de groupe — aucun de ces onglets n'a d'onglet d'origine. Ce chemin passe **avant** le domaine : chercher « github actions » et ouvrir trois résultats GitHub donne « Github actions », pas « GitHub », ce qui est le sujet réel
  - `planSearchGroup()` / `keywordsOf()` / `sameWord()` — **deux recherches différentes sur un même sujet fusionnent**. `QUERY_STOPWORDS` retire les mots qui disent *comment* on cherche (`meilleur`, `comparatif`, `trouver`, `avis`, `prix`…) et non *ce* qu'on cherche ; il reste les mots porteurs. Deux mots désignent le même sujet s'ils sont identiques ou partagent une racine d'au moins 5 lettres — c'est ce qui rapproche `garage` de `garagiste` et `panneaux` de `panneau`. Le groupe prend pour titre les mots communs à tous ses membres, dans la variante la plus courte (« Garage », pas « Garagiste »). Sans ce filtrage, « trouver garagiste » et « meilleur garage comparatif » n'auraient aucun mot en commun et donneraient deux groupes
  - **Deux seuils différents**, selon la force du signal : deux recherches *différentes* convergeant sur un même mot suffisent à créer le groupe (`plan.merged` → seuil 2), parce que c'est une intention délibérée ; une même requête répétée reste soumise à `MIN_TABS_TO_GROUP`, comme le regroupement par domaine
  - Cas volontairement préservé : si toutes les recherches sont **identiques**, la requête entière reste le titre. La réduire à ses mots porteurs l'abîmerait (« week-end lisbonne » deviendrait « Week end lisbonne »)
  - `groupFitsQuery()` — une nouvelle recherche rejoint un groupe existant si tous les mots du titre se retrouvent dans la requête : « hôtel lisbonne » atterrit dans « Lisbonne »
  - `stampActivity()` — horodate un onglet à l'activation ET au chargement complet (corrige le bug de Tab Ghost où un onglet ouvert en arrière-plan n'était jamais daté). Les horodatages vivent dans `chrome.storage.session`, pas `local` : ils sont vidés à chaque session, donc un ID d'onglet recyclé après redémarrage n'hérite pas d'une vieille date
  - `ensureAlarm()` — l'alarme n'est créée que si elle n'existe pas déjà. En MV3 le service worker redémarre à chaque événement ; un `alarms.create()` en tête de fichier remettait son compteur à zéro en boucle et elle ne se déclenchait jamais sur un navigateur actif
  - L'alarme `checkGroups` (1×/min) parcourt les **groupes**, pas les onglets un par un : un groupe s'endort si aucun de ses onglets n'a d'activité récente, qu'aucun n'est actif, et qu'aucun n'est whitelisté
  - `sleepGroup()` préfixe le titre du groupe avec `💤 ` et discard tous ses onglets. Il repart de `topicOfGroup()` et non de `group.title`, sinon un groupe déjà en `⏳ ` deviendrait `💤 ⏳ Sujet`
  - `WAIT_MIN` est désormais utilisé : à mi-parcours, le groupe est préfixé `⏳ ` — l'utilisateur voit le sommeil venir dans sa barre d'onglets. Le préfixe est retiré si l'activité reprend avant l'échéance
  - `chrome.runtime.onMessage` — `sleepNow` / `wakeNow`, pilotés par les boutons du popup. `wakeNow` réhorodate tous les onglets du groupe : réveiller, c'est repartir d'un compteur neuf
  - `wakeTabIfSleeping()` retire le préfixe `💤 ` dès qu'un onglet du groupe redevient actif
  - `bestSuggestion()` — **un seul chemin : l'habitude observée.** Le lexique `CATEGORY_HINTS` n'est plus proposé, puisque `groupByCategory()` l'applique déjà tout seul : le suggérer en plus n'ajoutait rien de visible et écrivait dans les réglages des lignes qui répétaient mot pour mot ce que le lexique fait. La suggestion ne sert donc plus qu'à ce que Wisp ne sait **pas** — les sujets propres à l'utilisateur
  - `habitSuggestion()` — grappes observées, construites **autour d'une graine** et non par composantes connexes. Chaque membre doit avoir été mesuré avec la graine elle-même ; sinon la grappe enflait par contagion (A-B, B-C, C-D produisait un sujet de quatre domaines où A et D ne s'étaient jamais croisés, d'où des titres du genre « GitHub + Graphiste + Jitter + Motion »). Plafond `MAX_CLUSTER` = 4
  - `recordCooccurrence()` — une paire ne compte qu'**une fois par heure** (`lastBucket`) : sinon un onglet laissé ouvert toute la journée simulerait 480 « rencontres » et le seuil se déclencherait sur du bruit plutôt que sur une habitude
  - `linkCluster()` — **n'écrit pas** une entrée dont le sujet est déjà celui du lexique pour ce domaine : la ligne serait un doublon sans effet, et les réglages doivent rester lisibles. Sinon il écrit le mapping, met `LINKED_DOMAINS` à jour immédiatement (sans attendre le rappel de `storage.onChanged`, sinon `regroupTopic()` regrouperait avec l'ancien mapping) puis rassemble les onglets concernés
  - **Wisp Pro — en sommeil.** `MONETISATION_ACTIVE = false` : aucun plafond, aucune mention de licence dans l'interface. Tout le mécanisme reste câblé et se rallume en repassant cette seule constante à `true`. Raison du gel : gater l'archivage revenait à mettre un péage sur une fonction que personne n'avait encore demandée, sur un produit à zéro utilisateur. Les payants qui marchent dans ce segment (Workona, Toby, Partizion) font payer la **continuité entre machines** et les espaces de travail, jamais une limite de stockage local — c'est là qu'il faudra regarder quand l'usage réel aura parlé. Le mécanisme, lui, est bon : achat unique, pas d'abonnement. `LICENCE_PUBLIQUE` est une clé publique ECDSA P-256 embarquée ; `verifyLicence()` vérifie la signature via `crypto.subtle`, **entièrement hors ligne**. C'est le point clé : la promesse « aucun appel réseau » vaut aussi pour le payant, donc aucun serveur à héberger. `tools/licence.mjs --keygen` a produit la paire (privée dans `tools/licence-privee.json`, **jamais versionnée**), `--sign <email>` émet une clé. Format `WISP-<charge>.<signature>` en base64url — le séparateur est un **point**, jamais un tiret : le base64url contient lui-même `-` et `_`, et une regex gourmande coupait au milieu de la signature
  - `FREE_ARCHIVE_LIMIT` = 3. Le plafond porte sur la **création** d'une archive, jamais sur celles déjà en place : un utilisateur qui repasse en gratuit ne perd rien. `archiveGroup()` rend `{ok:false, raison:"plafond"}` que le popup traduit en message
  - `archiveGroup()` / `restoreArchive()` / `deleteArchive()` — l'archivage ferme un groupe entier en gardant `{topic, color, savedAt, tabs:[{url,title}]}` dans `chrome.storage.local.archives` (plafonné à `MAX_ARCHIVES`). C'est la contrepartie du sommeil : endormir libère la RAM, archiver libère l'attention
  - `focusOnActiveGroup()` — mode focus : tout groupe de la fenêtre autre que celui de l'onglet actif est endormi ; les groupes whitelistés ou déjà endormis sont seulement repliés
  - Menu contextuel `wisp-group-selection` : regroupement manuel pour les cas que l'auto-détection ne capte pas (onglets sans domaine ni sujet commun)
- **`popup.html`** / **`popup.js`** — Deux moitiés :
  - **État en direct** (visible d'emblée) : bouton Mode focus, puis la liste des groupes avec la pastille de couleur, l'état (`Endormi` / `⏳ Dort dans X min` / `Ouvert sous tes yeux` / `Protégé par ta whitelist` / `Sans titre — Wisp l'ignore`) et deux actions (Dormir/Réveiller, Archiver). Puis la liste des archives (Restaurer / Oublier). Tous les boutons passent par `chrome.runtime.sendMessage` et redessinent ensuite depuis l'état réel — le popup ne maintient aucun état local. `render()` construit les listes hors de la page puis les remplace d'un coup (`replaceChildren`) : vider d'abord puis attendre les réponses de Chrome faisait « sursauter » le popup. Il lit `chrome.storage.session` directement (c'est un contexte de confiance).
  - **Réglages** (repliés dans un `<details>`) : seuil de regroupement, délais ⏳/💤, mapping domaines liés (format `domaine = Sujet`, une ligne par entrée), whitelist. Les deux compteurs du haut sont « Onglets endormis » et « Groupes archivés » — deux chiffres mesurés. L'ancienne carte « RAM libérée » a été retirée : c'était `count × 50` codé en dur, et l'API `chrome.processes` qui permettrait une vraie mesure n'existe qu'en canal dev.

## Invariants clés

- Les **titres français** produits par l'extension (catégories « Achats », « IA », « Veille »…, « Google Agenda », « Nouveau groupe ✏️ ») doivent rester identiques **à l'octet près** à ceux de la 1.0.0. Wisp retrouve un groupe existant par son titre : changer un seul caractère ferait naître un doublon chez chaque utilisateur français. Un test le vérifie pour les catégories. Conséquence assumée : un utilisateur qui change la langue de son navigateur verra ses nouveaux groupes prendre des titres anglais (« Shopping ») à côté des anciens (« Achats »).

- L'état d'un groupe vit **dans son titre**, sous forme de préfixe : `"💤 "` endormi, `"⏳ "` en sursis, rien = actif. C'est le seul stockage d'état de groupe — il n'y a pas de registre parallèle. Toute lecture de titre passe donc par `topicOfGroup()` / `isSleeping()` / `isWaiting()`, jamais par `group.title` brut, et toute écriture repart du sujet nu.
- `getBaseDomain()` s'appuie sur `COMPOUND_SUFFIXES`, une approximation de liste de suffixes publics (`.co.uk`, `.com.au`…). Sans elle, `amazon.co.uk` donnait le domaine de base `co.uk`, donc un groupe nommé « Co ». Une vraie PSL reste préférable pour une couverture internationale complète.
- Un groupe porte un **sujet lisible**, jamais une adresse : `prettyTopic()` transforme `github.com` en « GitHub ». La casse des marques ne s'algorithmise pas, d'où la table `BRAND_NAMES` ; le fallback capitalise simplement le premier label (`monsite.fr` → « Monsite »). Renommer une entrée de `BRAND_NAMES` casse la correspondance avec les groupes déjà créés sous l'ancien nom — ils deviennent des doublons.
- Les requêtes de recherche vivent dans `chrome.storage.session` sous `q_<tabId>`, comme les horodatages `t_<tabId>`, et sont purgées par le même `tabs.onRemoved`. Une requête de moins de 3 caractères est ignorée (bruit).
- Le rapprochement de deux requêtes est **lexical, jamais sémantique** : mots vides retirés, racine commune de 5 lettres. Il ne rapprochera donc jamais « salle de sport » et « basic fit ». C'est assumé — le prix à payer pour qu'aucune donnée ne sorte du navigateur.
- Au-delà de **deux** domaines sans métier reconnu, `habitSuggestion()` ne propose **aucun nom** : le champ du popup reste vide et le bouton « Lier » est désactivé tant que l'utilisateur n'a pas écrit. Une concaténation de marques fait un titre illisible, qui atterrit ensuite dans la barre d'onglets *et* dans les réglages. `linkCluster()` refuse d'ailleurs un nom vide plutôt que d'en fabriquer un.
- `CATEGORY_HINTS` est une table en dur, **pas de la sémantique** : elle ne sert qu'à proposer un nom crédible, et l'utilisateur peut toujours le réécrire avant de valider. Aucun appel réseau nulle part dans la chaîne de suggestion.
- `cooccurrence` et `dismissedSuggestions` vivent aussi dans `chrome.storage.local` hors de `SETTINGS_KEYS`, pour la même raison qu'`archives`.
- Si la monétisation est rallumée un jour : elle doit verrouiller **l'échelle**, jamais des fonctions coupées. Le regroupement par session de recherche est la vraie singularité de Wisp face à OneTab, Toby ou Workona — le brider tuerait ce qui donne envie d'installer. Le gratuit doit rester un bon produit, pas une démo.
- `archives` vit dans `chrome.storage.local` mais **ne figure pas dans `SETTINGS_KEYS`** : archiver ne doit pas déclencher un rechargement des réglages.
- `LINKED_DOMAINS` est un mapping local, saisi à la main par l'utilisateur dans le popup — aucune détection sémantique, aucun appel réseau, tout reste dans `chrome.storage.local`.
- Le seuil `GHOST_MIN` s'évalue sur la **dernière activité du groupe** (max des timestamps de ses onglets), pas sur un onglet isolé.
- Les réglages numériques sont bornés **des deux côtés** (`readNumber()` dans `popup.js`, `toPositiveInt()` dans `background.js`). Un champ vidé produit `NaN`, que `chrome.storage` sérialise en `null` — et `storage.get({k: défaut})` ne rend le défaut que si la **clé est absente**, pas si elle vaut `null`. Sans ce garde-fou, un seuil retombe à 0 et tout s'endort au premier passage.
- `chrome.storage.onChanged` ne doit réagir qu'aux clés de `SETTINGS_KEYS` en zone `local`, sinon chaque écriture relance `init()`.

## Pistes non implémentées

- Distinction entre les groupes créés par Wisp et ceux créés à la main par l'utilisateur : aujourd'hui la patrouille endort **tout** groupe portant un titre, y compris ceux que l'utilisateur a faits lui-même (un groupe sans titre, lui, est ignoré)
- `SERVICE_HOSTS` / `NEVER_GROUP` sont des listes en dur dans `background.js`, non éditables depuis le popup
- Détection des onglets zombies (jamais touchés depuis X semaines) à fermer en lot
- Recherche dans les onglets endormis et archivés, export/import de sessions
